## FENZ K codes

Trucks report their status over the radio as a K code. The app shows the K code with every truck
status (`stateText()` in `web/src/core/derive.ts`, e.g. "K1 Responding"). Keep these in step with
`statusCodes` in `data/codebook.json` (generated by `tools/make_codebook.py`).

| K code | Meaning | App state (`ApplianceState`) | Colour |
|---|---|---|---|
| K0 | Not available | (not used yet) | |
| K1 | Proceeding / responding to an incident | `responding` | amber |
| K2 | In attendance at the incident | `at-incident` | purple |
| K3 | On radio, outside its normal turnout area | `out-of-area` | teal |
| K4 | On radio, inside its normal turnout area (available) | `available-radio` | blue |
| K7 | At its normal station | `on-station` | green |

States without a K code: `turned-out` (red, from a turnout tone call, not a status message),
`not-heard`, `status-unknown`.

Source: community list at radiowiki.org.nz ("Fire Radio Codes"); FENZ released a K code list under
the OIA (fyi.org.nz request 6498 "Updated K Codes List") — check it before adding K5/K6/K8+. Some
Tait selcall setups also use K7-style status numbers for things like power failure, so don't
assume every status message is in this table.

The SelCall tones that carry each K code (the `suffix` after `-` in a 13-tone message, e.g.
`F1A0C2`) are **placeholders** (`"demo": true`) until confirmed from real recordings.

## SelCall format (short)

- CCIR tones, E = 2110 Hz is the repeat tone.
- Station turnout: `182` + callsign, or `182` + station number + `0` for a whole-station call.
- Appliance message: `HEADER-SEP+BODY` (13 tones); short appliance call is header + final tone
  (`B` = priority, `C` = routine, `4` = turnout ack; unverified).
